# 批量发布门禁

[English](batch-release-gates.md) | 简体中文

多首歌曲或多个交付配置一起编码、提升或打包时使用这些门禁。一键入口与底层渲染器必须执行同一套门禁。

## AV1 4:2:0 批量视觉风格

AV1 4:2:0批量入口支持`--visual-style vinyl|spectrum|both`，默认使用
`vinyl`：

```powershell
uv run --no-sync python scripts/render_karaoke_direct_av1_420_album.py `
  --manifest <album-manifest> `
  --visual-style <vinyl|spectrum|both>
```

`spectrum`不要求vinyl输入或资源。`both`分别生成两个独立成品，一个使用vinyl、
一个使用spectrum，并分别记录媒体、报告、哈希和提升身份。同一song/profile的两种风格共享哈希一致的profile ASS，并按顺序发布；它不是合并视觉效果的单个输出。`--single-track`只选择一个song和一个profile；使用
`--visual-style both`时，可以为该song/profile生成两个版本。
`--lossless-companion`和`--full-decode`仍是显式opt-in，不会因所选风格或`both`
而隐式开启。每个生成的变体都必须单独执行发布门禁。

## 冻结生成

全量编码前记录参数指纹：源文件、时间轴覆盖、渲染器、报告和测试身份；显式歌手解析与颜色、副唱角色和顶部叠加几何；编码器、像素格式、CQ/CRF、预设、配置、音频、容器、字体、主歌词/注音字号、间距和渲染选项；以及选定的时间证据链和交付配置。不要把歌曲数量、提示数量、CQ、字号或文件名写死进通用技能。

## 隔离暂存

- 在已接受交付物之外的专用暂存目录编码。
- 渲染器和编码器必须正常结束；部分文件、旧输出、未验证配置或混合生成身份都应失败。
- 与上一个已接受版本比较单曲和总文件大小。异常数量级或不对称变化要暂停调查；文件大小只是信号，不是质量证明。
- 完整空解码默认关闭，是可选诊断，不是批量或发布强制门禁。仅缺少完整解码证据不得阻止提升、降低验证状态，也不得要求每个成品都具备解码退出码。若执行，映射目标流并记录每个真实退出码；未执行不得伪造成功。
- 为提示、最长短语、顶部叠加、注音例外和释放重叠冲突抽取边界帧。

## 多文件提升

Windows多文件提升不是一个事务。为每个文件记录暂存路径、目标路径、备份路径、前后哈希、生成ID和提升状态；移动前解析并限制所有路径，必要时保持同卷。逐个提升，最终路径探测和哈希验证通过后才记为完成。失败时停止并按逆序恢复已完成项，再次探测和哈希。部分成功不能报告为批量发布完成。

交付文件名应从清单统一生成：曲目号、显示标题、平台安全标点和扩展名。渲染器、最终化、播放列表、归档器和测试必须复用同一命名规则。公开交付目录中的媒体基本名应与归档中的媒体基本名完全一致；私有暂存名可不同，但清单身份和内容哈希必须一致。

## 归档与压缩

按明确的配置和白名单打包，禁止宽泛目录通配。排除部分文件、日志、私有探针、源文件、凭据和旧媒体；完整读取每个成员并验证CRC或格式完整性；每个媒体成员必须匹配已接受成品哈希和清单身份。记录归档哈希、成员清单、大小、媒体哈希和生成ID。

实际检查压缩方法；`.zip`扩展名不保证成员已压缩。对AV1、HEVC、AAC或MP4等已压缩输入，用代表性大文件比较中等与最高兼容级别的字节数、压缩比和耗时；节省很小时优先中等级别。普通交付优先兼容性好的ZIP DEFLATE。同步生成校验文件，并从最终归档重新生成根发布清单。

## 清理与证据

只有最终路径媒体、归档、成员哈希和根清单通过后，才清理本代拥有的部分文件、预览帧、隔离测试缓存和已确认冗余的旧回滚。保留最新有用回滚直到用户接受发布；未知归属或历史回滚不要擅删。清理后再次扫描部分输出并报告保留项。

发布报告必须包含参数指纹、干净测试结果、暂存清单、可选解码是否执行、实际退出码、抽样窗口、关键帧检查、大小漂移判断、提升清单、回滚状态、归档白名单、CRC/回读结果、内部哈希和最终成品哈希。
